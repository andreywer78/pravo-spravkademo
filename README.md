# ПравоСправка v2 — общая база и администратор

## Архитектура

GitHub Pages → `index.html`/`app.js` → Supabase Auth + PostgreSQL.

Возможности:
- регистрация и вход;
- публичный просмотр документов;
- общая база для всех пользователей;
- роль `admin`;
- создание/редактирование/удаление документов;
- автоматическое увеличение номера редакции;
- сохранение предыдущей версии в `law_revisions`;
- публикация новой редакции сразу для всех;
- RLS-защита: только администратор может менять документы.

## 1. Создать Supabase

Создайте проект на https://supabase.com/

Откройте **SQL Editor**, вставьте содержимое `supabase.sql` и запустите.

## 2. Создать первого пользователя

Откройте сайт после настройки и зарегистрируйтесь через кнопку «Войти».

В Supabase:
**Authentication → Users**

Скопируйте UUID своего пользователя.

В SQL Editor выполните:

```sql
update public.profiles
set role='admin'
where id='ВАШ-UUID';
```

## 3. Получить ключи

В настройках проекта найдите API:
- Project URL
- Publishable/anon key

Откройте `config.js` и замените:

```js
window.SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";
window.SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
```

На свои значения.

Никогда не вставляйте `service_role` key в сайт.

## 4. Загрузить на GitHub

Загрузите в репозиторий:
- index.html
- style.css
- app.js
- config.js

`supabase.sql` можно оставить в репозитории или удалить после настройки.

В GitHub:
Settings → Pages → Deploy from branch → main → /(root).

## 5. Как работает редакция

Когда администратор изменяет документ:
1. старая версия автоматически попадает в `law_revisions`;
2. номер версии увеличивается;
3. новая версия становится текущей;
4. изменение сразу появляется у всех пользователей.

## Важно

Это техническая демонстрация правовой базы. Не используйте включённые в стартовую версию фрагменты как замену актуальным официальным текстам законов. Для реального юридического применения необходима проверка действующей редакции по официальному источнику.
